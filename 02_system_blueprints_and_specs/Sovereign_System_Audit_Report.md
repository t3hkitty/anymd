3. anymd & LIBRARY_COMPANION_MD: THE MARKDOWN DATABASE ENGINE
The strategic necessity of  anymd  (Library_Companion_MD) is the creation of a vendor-agnostic, system-agnostic markdown database. By utilizing human-readable Markdown as the storage medium, the architecture prevents vendor lock-in and achieves 99.9% deduplication via fingerprint governors.The Three Pillars of anymd Infrastructure
* Pillar 1: Ingestion (  vault-webhook-server.cjs  ):  Utilizes the "Inbox" and Webhook protocols. Hardened against Express v5 routing errors (fixing the :folder? optional parameter fault by registering distinct /webhook/:vaultName and /webhook/:vaultName/:folder routes).
* Pillar 2: File Schemas:  Enforcement of standardized Markdown formatting to ensure data remains human-readable and parseable across decades.
* Pillar 3: Metadata Sidecars:  Deployment of persistent object-relational data sidecars to maintain relational integrity without corrupting the primary Markdown source.Technical Integrity & Local-First Sync  System integrity is managed by the anymd.db.md single-file manifest logic. Specialized modules support Physical Card Binder (TCG) scanning and Home Insurance Room Scanners. Terms and Profile registration are gated via the "meow" invite code protocol.The local-first sync architecture leverages WebDAV providers (specifically  Koofr ,  InfiniCLOUD , and Nextcloud) and n8n workflows. By running the vault-webhook-server.cjs on  Port 3050 , the system bypasses cloud-based SSL requirements while maintaining secure, local POST-based data ingestion. Furthermore, the integration of the  File System Access API  allows for mounting local directories directly within the browser, entirely bypassing browser cache limitations and centralized backend dependencies.
